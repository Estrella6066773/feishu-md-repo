# 文档写作规范

本规范定义 Docs 文档库的组织、命名、链接与更新约定，所有文档作者与编辑者须遵守。

## 文档分层

| 层 | 目录 | 回答 | 禁止 |
|----|------|------|------|
| 需求 | `Docs/01-需求/` | 需要解决什么问题、用户如何感知 | 具体类名、表结构、API 细节 |
| 设计 | `Docs/02-设计/` | 如何满足需求（架构、模块、数据、接口） | 逐行代码、营销语言 |
| 实现 | `Docs/03-实现/` | 程序如何实现（代码级走查、模块边界） | 重复需求/设计内容 |

跨层引用用链接而非复制正文；涉及「为什么这么设计」时写入决策记录（ADR）。

## 目录与命名

- 每个子目录必须有 `README.md` 索引，列出本目录全部文件与子文件夹。
- 正文文件命名采用「前缀-主题」形式：`需求-同步.md`、`设计-同步引擎.md`、`实现-同步流水线.md`。
- 决策记录命名 `ADR-序号-短标题.md`，序号递增。
- 文档扩展名统一 `.md`，正文用 UTF-8 编码。

## 内部引用

- 引用另一篇文档须写相对路径 Markdown 链接，禁止裸写文件名或「见某文档」。
- 每个正文文件须在文首或文末保留「返回本目录」链接。
- 需求文档的每个需求条目分配稳定编号（如 `R-同步-01`）；设计文档引用需求时写该编号并加链接。

## 元数据

每个正文文件在文首以表格或列表记录：

- 状态：草稿 / 待校验 / 已校验
- 最后更新：修改当天日期
- 关联设计 / 关联实现：被引用的对应层文档链接（可选）

编辑 `已校验` 文档前须经文档负责人确认；Agent 修改文档后状态降为「待校验」。

## 变更流程

| 变更 | 要求 |
|------|------|
| 新建 / 移动 / 删除文档 | 同步更新所在目录 README 索引与所有入链 |
| 修改正文 | 更新「最后更新」；若改动需求，回写受影响的设计与实现文档 |
| 新增架构决策 | 追加 ADR，并在 `02-设计/README.md` 索引登记 |
| 新增术语 | 在正文使用并回写 [词条库](./词条库.md) |
