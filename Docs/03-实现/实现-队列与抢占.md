## 2. 队列模型（SyncQueue）

进程内单消费者队列：

| 成员 | 说明 |
|------|------|
| `pending` | 待执行任务数组 |
| `running` | drain 循环进行中标记 |
| `activeTask` | 当前执行任务 |
| `enqueue(task, {front})` | 入队；`front` 为真时插队到队首 |
| `drain()` | 串行消费；单任务异常不阻断后续任务 |
| `hasSyncForBinding` | 该绑定是否已有同步在跑或排队 |
| `getQueueDepth()` | 深度 = 排队数 + 运行中 1；≥ 10 告警 |

任务类型 `QueuedBindingTask`：绑定 ID、日志 ID、类型（`sync` / `comment-import`）、触发、代际、执行函数。

## 3. 代际抢占

**代际（generation）** 是每个绑定上单调递增的计数器，用于判定任务是否过期：

```text
enqueueBindingSync(trigger)
 ├─ schedule 且已有任务在跑/排队 → 跳过（返回空 logId）
 ├─ isManualPreemptTrigger(trigger)？    # manual 与 bot 为抢占触发
 │    └─ preemptBindingTasks：代际 +1，取消排队任务，标记运行中任务过期
 ├─ 记录新任务代际 = 当前代际
 └─ enqueue(task, { front: preempt })
```

**过期检查**：任务执行中通过 `registry.isStale(bindingId, generation)` 判断；`runSync` 每步调用 `shouldAbort`，命中即抛 `BindingTaskPreemptedError`。

**取消语义**：被抢占的任务日志标记为「已被新的手动指令打断」，运行中任务仍在 `finally` 里解除登记，保证队列后续任务不被阻塞。

## 4. 定时器（Scheduler）

- `refresh(db, ...)` 遍历绑定，为开启定时者创建 `setInterval`；
- 定时回调：入队同步任务；绑定开启 `commentImportOnSchedule` 时连带入队评论导入；
- `stopAll()` 清除全部定时器；刷新时先停后建，避免重复计时。

定时触发的同步在协调器内先做一次快检：SHA 无变化且无强制更新 glob 时直接跳过，日志记为「定时检查：无更新」。

## 5. 同步任务的执行前检查

`runBindingSyncTask` 在真正执行前：

1. 检查 `shouldAbort`——已过期则取消排队日志；
2. 登记运行中任务；
3. 绑定不存在 → 日志置 failed 并解除登记；
4. 定时触发时先做 SHA 快检（见上）；
5. 调用 `runSync` 或 `runCommentImport`，完成/失败后通过播报器通知。

## 6. 失败处理

| 场景 | 处理 |
|------|------|
| 任务被抢占 | 日志置 failed（消息为抢占提示），不播报失败 |
| 任务执行异常 | 日志置 failed，记录错误信息，播报失败 |
| 队列消费异常 | 记录日志，继续消费下一个任务 |
