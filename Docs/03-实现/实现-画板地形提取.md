## 1. 模块边界

```text
飞书画板 --whiteboardNode.list--> packages/feishu/board-terrain.ts --几何体 JSON-->
  core-service POST /api/toolbox/board-terrain/extract <-- UI 工具箱「画板地形」页
几何体 JSON --文件--> Unity Editor 工具 BoardTerrainImporter.cs --预制体--> ShipBuild 场景
```

## 2. 关键实现点

### 2.1 飞书侧：`packages/feishu/src/board-terrain.ts`

- `extractBoardTerrainShapes(client, whiteboardId, colors)`：
  - 复用 `export/board-export.ts` 的 `listWhiteboardNodes()` 读取全部节点；
  - 只保留 `type === 'composite_shape'` 的节点；
  - 形状细分：`ellipse` → `kind: 'ellipse'`；`rect` / `round_rect` → `kind: 'rect'`；其余形状忽略；
  - 颜色过滤：`style.fill_color` 与目标色都归一化（去 `#`、转小写）后比对，仅保留命中项；
  - 输出携带画板坐标（px，y 向下为正）、宽高、旋转角。
- `parseFeishuBoardUrl(url)`：从 `…/board/<token>` 提取画板 ID。
- `resolveBoardTerrainWhiteboardId(client, url)`：链接解析统一入口——画板直链直接取 ID；`docx` / `wiki` 云文档链接经 `board-service.ts` 的 `findBoardWhiteboardId` 在正文定位第一个画板块后取 `whiteboard_id`；其余链接报错。

### 2.2 core-service：`apps/core-service/src/app.ts`

- 新增 `POST /api/toolbox/board-terrain/extract`：
  - 请求体支持 `boardUrl`（画板直链或含画板的云文档链接）或 `whiteboardId`（优先），`colors` 必填且非空；
  - `boardUrl` 经 `resolveBoardTerrainWhiteboardId` 统一解析为 `whiteboard_id`，再调用 `extractBoardTerrainShapes`；
  - 返回 `ok / whiteboardId / shapes / totalNodeCount / matchedShapeCount`。
- 能力登记：`packages/shared/src/api-contract.ts` 的 `CORE_API_FEATURES` 增加 `board-terrain-extract`，`CORE_API_VERSION` 由 7 升到 8。

### 2.3 UI：`apps/ui/src/pages/toolbox/BoardTerrainTool.tsx`

- 输入：画板直链 + 可增删的颜色列表（默认 `#6db5a3`、`#e0865f`）；
- 点击「识别地形几何体」调用 `extractBoardTerrain()`（`apps/ui/src/lib/queries.ts`）；
- 结果表格展示类型、颜色、x、y、宽高、旋转，支持复制 JSON 与下载 JSON；
- 导出的 JSON 顶层含 `shapes` 数组，字段与 `BoardTerrainShape` 一致。
- 工具箱注册：`ToolboxPage.tsx` 新增 `terrain` tab，tab 网格由两列改为三列。

### 2.4 Unity 侧：`D:/Unity/Spaceship/Assets/Scripts/Tools/Editor/BoardTerrainImporter.cs`

- 菜单 `Tools/画板地形/从 JSON 生成（窗口）` 打开复刻窗口；
- `RebuildTerrainInScene(jsonPath, circlePrefab, squarePrefab, pixelsPerUnit, rootName, mergeIntoExistingRoot)` 为可独立调用的复刻入口，窗口按钮与自动化脚本共用；
- JSON 解析兼容两种形态：工具箱导出的完整对象、以及裸 `shapes` 数组（`BoardTerrainDocument.Parse` 自动包裹）；
- 坐标映射：
  - **锚点**：画板所有形状（圆/椭圆/矩形）的 `x/y` 均为旋转前包围盒的左上角，**不存在「椭圆即质心」的差异**；质心按 `(x, y) + R(-angle) · (width/2, height/2)` 换算，`R(θ) = [cosθ, -sinθ; sinθ, cosθ]`（此处 `angle` 代入 `-angle`）；
  - 画板 y 向下为正 → Unity y 取负；
  - `localScale = (width, height, 1) / pixelsPerUnit`（`Circle.prefab` 与 `Square.prefab` 均为 1×1 单位）；
  - `localEulerAngles.z = -angle`（y 翻转后旋转方向取反）；
- 墙体放入场景根节点「画板地形」，支持合并到已有根节点或先清空重建。

## 3. 验证记录

- 全部包 `tsc --noEmit` 通过；
- 用样例 JSON（5 个几何体：2 圆 3 矩形）在 `ShipBuild` 场景复刻，生成「画板地形」根节点及 5 个墙体；
- 抽查变换数值：圆形 `(x=200, y=150)` → `pos=(2, -1.5)`，`width=400` → `scale=(4, 4)`，`angle=15` → `euler z=345`，符合映射约定；
- 真实画板验证：从云文档链接 `docx/IIdPdeB2do3c8Bx3D6AcXgffnre` 定位画板 `Dk03wOZShh2LKhbQpVcccDfmn3c`，指定色 `#BBBFC4` 命中 266 个几何体（234 圆 + 32 矩形），导出 JSON 后在 `ShipBuild` 场景复刻出 266 个墙体，数量与分布与画板一致。
- **锚点校准**（2026-08-04）：此前将椭圆当作「质心锚点」、矩形当作「左上角锚点」分别处理，导致圆与矩形的相对位置整体错位（用户场景中 8 个参照物手动校准后仍对不上）。经用户提供 1:1 复刻参照文档（docx `SwR5diuLkotIlBxKGoGcmJ7Mnuf`，白板 8 节点）对照验证：**圆/椭圆/矩形统一为左上角锚点**，按上述公式换算质心后，8 个参照物与场景手动摆放位置仅差一个全局平移（偏移范围 < 0.006 单位），内部相对位置与旋转方向完全一致。`BoardTerrainImporter.cs` 已据此统一换算逻辑。
