# 实现-同步流水线

- 状态：待校验
- 最后更新：2026-08-01
- 关联设计：[设计-同步引擎](../02-设计/设计-同步引擎.md)

本文对 `packages/core/src/engine.ts` 的 `runSync` 做代码级走查。

## 1. 入口与调用链

`runSync` 由 `apps/core-service/src/sync-coordinator.ts` 调用。调用方职责：解析绑定、判定触发、处理抢占与播报；`runSync` 只负责一次同步的完整执行。

核心参数（`RunSyncOptions`）：

| 参数 | 作用 |
|------|------|
| `binding` | 绑定配置 |
| `trigger` | 触发来源，影响消息与行为 |
| `fullResync` | 修复同步：全库结构检查 |
| `forceRewriteAll` | 强制重写全部正文（跳过块特征校验） |
| `repairMissingRemote` | 手动/机器人同步时补建缺失节点 |
| `shouldAbort` | 抢占检查回调 |
| `docWriteConcurrency` | 正文写入并发数 |

## 2. 主流程

```text
runSync
 ├─ 创建/更新同步日志（status=running, phase=planning）
 ├─ 解析飞书凭证（无则报错）
 ├─ 创建 Git Provider（cloud 时先 fetch）
 ├─ 取 toSha / fromSha
 ├─ resolveSyncPaths → treePaths / changedPaths
 ├─ 取 commits（between fromSha..toSha）
 ├─ 规划器 buildPlan → SyncPlan
 ├─ executePlan（structure → content → cleanup → overview）
 ├─ 收尾：
 │   ├─ 更新绑定 lastSyncedSha / lastSyncedAt
 │   └─ 更新同步日志 success + 消息
 └─ 异常路径：日志置 failed 后重抛
```

## 3. 规划阶段（planning）

`createPlanner(binding.syncMode)` 返回工作区或仓库规划器：

- 工作区规划器：以文档扩展名筛选，决定 `ensure_folder` / `ensure_doc` / `update_doc`；
- 仓库规划器：按 README 目录结构生成嵌套文档计划。

计划产物 `SyncPlan` 含操作列表、全部跟踪路径、`gapFillOnly` 标记。

补建缺失节点：当 `gapFillOnly` 或 `repairMissingRemote` 为真时，`buildRepairOperationsForMissingRemote` 依据父节点子数量检测飞书侧缺失的已映射文件，生成追加的 `ensure_doc` 操作并排序。

## 4. 结构阶段（structure）

遍历计划操作，逐项执行：

| 操作 | 行为 |
|------|------|
| `ensure_folder` | 检查映射与远程存在性，缺失则创建文件夹并写映射 |
| `update_doc` / `ensure_doc` | 解析父 token → 确保文档节点 → 入正文待写队列 → 更新映射 |
| 表格文件（`drive_file` 模式） | 上传原文件并写映射，不计入正文队列 |

父节点 token 解析：优先查映射表，缺失回退到目标根父 token。

## 5. 内容阶段（content）

文档正文写入在 `pendingDocUpdates` 队列上以并发执行（`runTasksWithConcurrency`）。强制重写时并发降为 1（串行）。

每个文档的处理顺序：

1. 重写内部 Markdown 链接（映射表 → 飞书文档 URL）；
2. 计算重写后正文哈希（`hashDocumentSyncContent`：Markdown + 图片 blob + 哈希版本号）；
3. 依据 [设计-同步引擎-正文写入决策](../02-设计/设计-同步引擎.md) 决定是否写入；
4. 需要写入时 `adapter.updateDocumentContent`（含图片解析、表格模式）；
5. 写回 `contentSha` 到映射。

**频控重试**：`writeDocumentContentResilient` 捕获限流错误，指数退避（`min(400 * 2^attempt, 30_000)`）重试整篇；每次重试前检查 `shouldAbort`。

## 6. 清理阶段（cleanup）

`deleteRemovedNodes`：以当前树路径集合筛选历史映射，剔除保留路径，按路径深度从深到浅删除飞书节点并清理映射。删除失败的节点视为已删除，仅清理本地映射（避免孤儿数据阻塞后续同步）。

## 7. 总览阶段（overview）

`syncOverviewWhiteboard` 更新根级「同步文档总览」画板思维导图。失败仅告警，不使整个同步失败。

## 8. 完成消息与无操作判定

同步完成消息依据以下分支生成：

- 增量无操作（`isIncrementalNoop`）：无操作、有 fromSha、非修复同步；
- 补缺无操作（`isGapFillNoop`）：`gapFillOnly` 且操作数为 0；
- 修复同步：校验 / 修复 / 跳过计数；
- 强制重写：操作数；
- 常规：操作数与总览更新状态。

异常判定：无操作且非上述无操作场景时，抛「无可同步文件」或「未写入任何内容」错误，提示排查路径、分支或 README 配置。
