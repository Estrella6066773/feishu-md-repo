# 设计-同步引擎

- 状态：待校验
- 最后更新：2026-08-01
- 覆盖需求：[需求-同步](../01-需求/需求-同步.md)（R-sync-*）

## 1. 职责

同步引擎（`packages/core` 的 `runSync`）把绑定对应的 Git 树镜像到飞书目标，按固定阶段推进。调用方为 [apps/core-service](../03-实现/实现-包结构导览.md) 的同步协调器。

## 2. 五阶段流程

| 阶段 | 职责 | 产出 |
|------|------|------|
| planning | 解析路径、构造同步计划 | `SyncPlan`（操作列表） |
| structure | 执行结构操作：建文件夹、建/更新文档节点 | 节点映射更新 |
| content | 写入文档正文（并发） | 正文 + 图片 + 表格 + 图表 |
| cleanup | 清理 Git 中已删除文件的飞书节点与映射 | 删除计数 |
| overview | 更新「同步文档总览」画板 | 总览思维导图 |
| done | 收尾写日志、更新绑定 `lastSyncedSha` | 同步日志 success |

## 3. 同步计划（SyncPlan）

规划器按同步模式区分：

- **工作区模式**（workspace-planner）：默认同步文档扩展名与 CSV；
- **仓库模式**（repository-planner）：每含 README 的目录 → 一篇文档，子文档嵌套。

`SyncOperation` 类型：`ensure_folder` / `ensure_doc` / `update_doc` / `delete` / `move`。

补建缺失节点：立即同步/机器人同步时（`repairMissingRemote`）或补缺同步（`gapFillOnly`）时，通过父节点子数量检测缺失的已映射文件，追加 `ensure_doc` 操作。

## 4. 正文写入决策

对每个待写文档，引擎先计算「重写后正文哈希」（Markdown + 图片 blob + 哈希版本号），再据以下规则决定是否写入：

| 条件 | 行为 |
|------|------|
| `forceWrite` / `forceRewriteAll` | 直接写入 |
| 内容从未同步或哈希变化 | 写入 |
| 修复同步（`fullResync`）且飞书块特征校验通过 | 跳过（verified） |
| 修复同步且校验发现异常 | 写入（修复） |

频控处理：整篇写入遇限流按指数退避重试（上限 30 秒），满足 [NFR-rel-02](../01-需求/非功能需求.md)。

## 5. 图片与内部链接

- 图片：解析 Markdown 图片引用 → 从 Git 读取二进制 → 上传为 Image Block；远程图片按需下载（不保留 GitHub 链接）。
- 内部链接：重写相对 Markdown 链接为目标飞书文档 URL（含锚点），依赖节点映射表。

## 6. 清理语义

`deleteRemovedNodes` 依据「当前 Git 树路径集合」筛选历史映射：保留保留路径与仍存在于树中的路径，其余按深度从深到浅删除并清理映射。

## 7. 完成消息

同步完成后按操作数与场景生成消息（无操作 / 补缺 / 修复 / 强制重写 / 常规），写入同步日志（[R-sync-21](../01-需求/需求-同步.md)）。
