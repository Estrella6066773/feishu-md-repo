# ADR-002：以 Git 为同步权威源

- 状态：已采纳
- 决策日期：2026-08-01

## 背景

同步方向存在两种可能：Git → 飞书（仓库为准）或双向同步（飞书也可写回 Git）。约束条件：

- 团队希望仓库内容可审查、可版本化（[需求总览-问题背景](../../01-需求/需求总览.md)）；
- 双向同步需要处理冲突仲裁与飞书格式反解，复杂度显著上升；
- 需求明确「不把飞书文档当作可写回 Git 的双向权威编辑器」。

## 决策

**以 Git 为同步权威源**：只同步 Git 已跟踪路径，正文方向固定为 Git → 飞书；评论作为例外允许反向导入仓库（[R-comment-*](../../01-需求/需求-评论回流.md)）。「Git 为准」同时意味着不扫描未跟踪工作区文件。

## 后果

**收益**

- 内容变更可追溯（commit 级别），飞书侧只需镜像；
- 同步判定可依赖 Git SHA 与内容哈希，增量同步成本低；
- 避免冲突仲裁这一复杂问题域。

**代价**

- 飞书侧编辑的正文不会自动回写仓库（须用工具箱的导出功能）；
- 用户在飞书的即时修改可能被下次同步覆盖——由节点映射与正文哈希跳过逻辑缓解。

## 替代方案

| 方案 | 未采用理由 |
|------|-----------|
| 双向同步 | 冲突仲裁、格式反解复杂，与需求非目标冲突 |
| 飞书为准 | 违背「仓库可审查、可版本化」的出发点 |
