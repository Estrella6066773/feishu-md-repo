# ADR-001：本地优先与单机 SQLite

- 状态：已采纳
- 决策日期：2026-08-01

## 背景

系统需要持久化飞书凭证、绑定配置、节点映射与日志。备选存储方案包括：本机 SQLite、集中式云数据库、配置文件（JSON/YAML）。

约束条件：

- 凭证含 `app_secret`，不应离开用户本机（[NFR-sec-01](../../01-需求/非功能需求.md)）；
- 目标是「每人在本机配置飞书自建应用」，无多用户云端账号体系（[需求总览-非目标](../../01-需求/需求总览.md)）；
- 需要结构化的多表查询（绑定、映射、日志、事件）。

## 决策

采用**本地优先**架构：核心服务默认只监听 `127.0.0.1`（[NFR-sec-02](../../01-需求/非功能需求.md)），数据存本机 **SQLite**（Drizzle ORM），凭证与映射不进入仓库。

## 后果

**收益**

- 凭证不出本机，安全边界清晰；
- 零部署成本，无需外部服务；
- Drizzle 提供类型安全 schema 与迁移机制。

**代价**

- 不支持多用户共享数据；
- SQLite 单写者模型对高并发写有上限（本场景可接受）。

## 替代方案

| 方案 | 未采用理由 |
|------|-----------|
| 集中式云数据库 | 与「本机应用」定位冲突，引入运维与数据暴露面 |
| 配置文件存储 | 无查询能力，绑定/映射/日志关系无法表达 |
| 嵌入式 KV（如 leveldb） | 无 SQL 关系查询，无法满足日志与事件追溯需求 |
