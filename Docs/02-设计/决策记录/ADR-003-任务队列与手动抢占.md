# ADR-003：任务队列与手动抢占

- 状态：已采纳
- 决策日期：2026-08-01

## 背景

多个绑定可能同时触发同步；同一绑定也可能被定时、手动、机器人指令并发触发。若不控制并发：

- 同一绑定并发写飞书会互相覆盖节点映射；
- 大批量任务堆积会导致长尾阻塞与频控风险。

约束条件：需求要求「同绑定上新的手动任务可抢占进行中的旧任务」（[需求总览-设计原则](../../01-需求/需求总览.md)）；定时触发不应叠队（[NFR-rel-04](../../01-需求/非功能需求.md)）。

## 决策

采用**单消费线程 + 任务代际（generation）抢占**：

- `SyncQueue` 为进程内队列，串行执行任务（[实现-队列与抢占](../../03-实现/实现-队列与抢占.md)）；
- 每个绑定维护一个递增代际；手动/机器人触发为「抢占触发」，入队前置调用 `preemptBindingTasks` 使旧任务过期；
- 旧任务在执行点检查 `shouldAbort`，抛 `BindingTaskPreemptedError` 结束；
- 定时触发在绑定已有任务在跑或排队时直接跳过。

## 后果

**收益**

- 同一绑定任意时刻只有一个有效任务，避免映射覆盖与写冲突；
- 手动指令能及时获得执行权，用户体验好；
- 队列有界（串行 + 积压告警）。

**代价**

- 任务无法跨进程水平扩展（本机单进程场景可接受）；
- 被抢占任务已写入的飞书侧变更不会自动回滚（幂等写入缓解）。

## 替代方案

| 方案 | 未采用理由 |
|------|-----------|
| 多线程并发执行 | 需要锁与事务协调，复杂度高，收益有限 |
| 任务取消后回滚 | 飞书侧无事务回滚能力，回滚语义不可实现 |
