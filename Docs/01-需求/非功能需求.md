# 非功能需求

- 状态：待校验
- 最后更新：2026-08-01

本文集中定义跨主题的非功能需求，供设计层约束引用。

## 安全

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| NFR-sec-01 | 飞书凭证（appId / appSecret）只存本地 SQLite，不写入仓库 | 必须 | 提交前 `check:secrets` 无密钥 |
| NFR-sec-02 | 核心服务默认只监听 `127.0.0.1`，不对公网暴露 | 必须 | 绑定地址为回环地址 |
| NFR-sec-03 | 仓库不提交 `.env`、本地 `*.db`、`node_modules` | 必须 | `.gitignore` 覆盖 |
| NFR-sec-04 | 提供密钥扫描脚本供提交前运行 | 必须 | `pnpm check:secrets` 可执行 |

## 性能

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| NFR-perf-01 | 跨文档正文写入支持并发（默认读取环境变量），强制重写时降为串行 | 期望 | 大量文档时同步时间可接受 |
| NFR-perf-02 | 队列积压深度 ≥ 10 时告警 | 期望 | 日志出现告警 |

## 可靠性

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| NFR-rel-01 | 飞书 API 频控（限流）时自动等待并重试，支持持久化重试策略 | 必须 | 限流不导致任务整体失败 |
| NFR-rel-02 | 文档写入遇频控时按指数退避重试整篇（上限 30 秒） | 必须 | 重试后写入成功 |
| NFR-rel-03 | 同绑定上新的手动指令可抢占进行中的旧任务（代际机制） | 必须 | 旧任务被标记取消 |
| NFR-rel-04 | 定时同步在绑定已有任务进行中或排队时跳过，避免叠队 | 必须 | 不重复排队 |
| NFR-rel-05 | 飞书删除事件记录到本地（`feishu_deletion_events`），可追溯处理状态 | 期望 | 事件入库且状态可查 |
| NFR-rel-06 | 同步与评论导入任务异常时在日志记录原因，同步状态置为失败并播报 | 必须 | 失败信息完整 |

## 可观测性

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| NFR-obs-01 | 核心服务提供健康检查，含 API 版本号与能力列表；UI 判断服务是否过旧 | 必须 | 版本不兼容时 UI 提示 |
| NFR-obs-02 | 同步日志记录触发来源、前后 SHA、阶段、进度、当前文件 | 必须 | 日志表字段齐全 |
| NFR-obs-03 | 结构化日志按模块分层（sync / sync-queue / sync-coordinator / comment-import / bot 等） | 期望 | 日志可按模块过滤 |
| NFR-obs-04 | 面板可查看队列状态（运行中、排队数、当前任务） | 必须 | 状态接口数据正确 |

## 兼容性

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| NFR-comp-01 | 机器人用户权限判定兼容旧版 `open_id` 白名单逻辑（未配置权限名单时回退） | 必须 | 旧配置仍可用 |
| NFR-comp-02 | 旧绑定行为异常时可在面板重新保存一次以应用默认触发配置 | 期望 | 重新保存后配置生效 |
